# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Plain static HTML/CSS in one self-contained `showcase.html` file at the repository root. No build step, dependencies, or framework. It must open directly from the filesystem.

## Users

- **Primary learner:** Simon and other beginner coders browsing the projects with a parent. Their job is to choose the next small project and understand how the path grows.
- **Parent/teacher:** Uses the showcase as a shared map for explaining how each project builds toward the next.

## Product Purpose

A visual project directory for the teach-to-code collection. Success means a child can see what is ready, understand what each project teaches, and choose a working project without needing a separate index page.

## Positioning

The collection is presented as a learning journey: each project is a small real thing, and the route makes the progression from browser programs to a small strategy game visible.

## Operating Context

Opened directly from the filesystem in a browser. The showcase links to sibling project HTML files and must remain useful without a server or network.

## Capabilities and Constraints

- Working projects are Calculator and Elevator, linking to `01-calculator/calculator.html` and `02-elevator/elevator.html`.
- Roadmap projects 3–18 and the small RTS target are represented as disabled future stops with “Coming Soon”.
- The route is intentionally winding and illustration-like rather than a conventional grid of cards.
- Card content must come from `ROADMAP.md`; do not invent finished project claims or links.
- No dependencies, build step, or external requests.

## Brand Commitments

The tone is encouraging, concrete, and family-friendly. Existing project worlds are distinct; the showcase may unify them as a path without replacing their individual identities.

## Evidence on Hand

- `ROADMAP.md` is the source of truth for the project sequence and teaching topics.
- `01-calculator/` and `02-elevator/` contain the two working project pages.
- No public testimonials, benchmarks, or commercial claims exist; none should be fabricated.

## Product Principles

1. Make the next project obvious.
2. Show the learning progression, not just a file list.
3. Keep the source readable and directly runnable.
4. Let visual delight earn attention without hiding project truth.

## Accessibility & Inclusion

Use semantic headings, real links for available projects, disabled non-links for future projects, visible keyboard focus, sufficient contrast, and responsive layouts that remain understandable on small screens.
