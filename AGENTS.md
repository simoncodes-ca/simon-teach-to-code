# AGENTS.md

Teaching scaffolds that an 11-year-old fills in to learn programming. Each numbered folder is one project: a finished, good-looking web page whose JavaScript is deliberately unfinished.

## The rule that overrides everything

**The stubs are the deliverable. Leave them unwritten.**

Every project ships a `.js` file whose core functions are empty, marked `// TODO`, and wrapped in graduated hints. Filling them in is the entire point of the repo — it is the learner's work, and completing it destroys the product.

So when a request sounds like "make the game work", "fix the elevator", or "the calculator returns nothing", the job is almost always to improve the *scaffold* — sharper hints, a stub reordered, a bug in the given wiring, a stub whose completion produces no visible change. Implement a stub only when the user says so in as many words.

To test that a scaffold is completable, fill the stubs in a throwaway copy or at runtime via `page.evaluate` — never in the tracked file.

## Project anatomy

Every `NN-name/` folder holds the same seven things:

| File | Role |
|---|---|
| `NN.html` | The page. Finished — every id and hook the implementation needs is already there |
| `styles.css` | The look. Finished |
| `NN.js` | **The scaffold.** Memory, then stubs, then given wiring |
| `README.md` | The learner's guide: concepts, vocabulary, what the wiring already does |
| `PRODUCT.md` | The product contract — scope, constraints, what is deliberately deferred |
| `DESIGN.md` | The visual system, recorded from the built page (absent for 02) |
| `assets/` | Images, fonts, sounds — all local, all relative paths |

`.impeccable/` is generated by the Impeccable design skill; only its `config.json` is tracked.

The `.js` file is organised in numbered sections: **the memory** (the handful of variables that hold all state), **your job** (the stubs), **the given wiring** (rendering, event handlers, setup). The learner is told to read the wiring but not edit it.

## Writing a stub

- **Graduated hints, three levels**, in this order: `Gentle hint:` names the idea, `Stronger hint:` names the method, `Answer if you want it:` gives the line. The learner chooses how far to read.
- **Order stubs so each one only needs what came before it.** The function that assembles the others goes last.
- **Every completed stub changes something on screen.** A stub whose payoff is invisible is a defect — check that the given wiring actually reads its return value.
- **Every function the learner must call is named in a comment.** A helper sitting in the wiring that nothing points at is unguessable.
- Plain language, no jargon. Repetition the learner can follow beats indirection they cannot.

Read the project's `PRODUCT.md` before changing scope — it records what is deliberately deferred, and "missing" features are usually held back on purpose.

## Hard constraints

- **No build step, no dependencies, no framework, no network.** The page must work by double-clicking the HTML.
- **Classic scripts only.** `file://` blocks ES modules, so no `import`/`export` and no `type="module"`.
- Relative asset paths throughout — the repo deploys to GitHub Pages from its root on every push to `main`.
- Sounds follow one pattern: build the `Audio` object once, reuse it, rewind with `currentTime = 0`, and swallow the pre-interaction autoplay refusal with `.catch(() => {})`.

## Verifying a change

Playwright drives a real browser and is the way to check any page change. Load the page from a `file://` URL, then assert on console errors, element geometry for layout claims, and a full play-through for logic.

Hangman established a convention worth copying: demo states behind a URL hash — `#demo`, `#demo-win`, `#demo-lose` — that make the finished look inspectable while the stubs are still empty. They work by standing in for unfilled stubs at runtime, so a demo that renders blank usually means a stub the demo forgot to cover.

## Adding a project

Sequence numbers are part of the folder name and the learning path. A new project means: the `NN-name/` folder with the seven files above, a card in `showcase.html` (`Ready` with a link, or a disabled `Coming Soon` article), and an entry in `ROADMAP.md` and the root `README.md`.

`index.html` only redirects to `showcase.html`.
